# Implementation decisions and reconstructions

The paper specifies much but not everything. Wherever this repository had to choose, the choice is listed here with the reason, the alternative, and where it lives in code. **Nothing in this file is a result.** If you disagree with a choice, change it, rerun, and record the change in the run manifest.

Legend: **P** = the paper states it. **R** = reconstruction (the paper is silent or ambiguous; this is our rule). Items marked R are the places where a reproduction can legitimately differ from the authors' unpublished code.

| ID | Topic | Status | Decision | Code |
|---|---|---|---|---|
| D-01 | Routing rule (Eq. 5) | P/R | Eq. 5 as printed is garbled. Section 3.8.1 gives the rule: `p < T_low` accept, `p > T_high` reject, both endpoints in the review band. Implemented as stated in 3.8.1. | `models/triage.py::route_probability` |
| D-02 | Fitting `(T_low, T_high)` | R | The published pairs are in `published.PUBLISHED_ROUTING_THRESHOLDS` and are used for D1-D5 by default. To refit (and for the synthetic fixture) the paper only says selection "prioritized validation AUPRC and expected operational cost" under an escalation cap. We minimise expected common-path cost (accepted frauds cost `c_FN`, rejected legitimates `c_FP`, each escalation `c_review`) subject to escalation <= cap (0.05; 0.35 on the tiny fixture). | `models/triage.py::select_thresholds` |
| D-03 | Rationale schema | R | Section 3.3.2 lists the fields (verdict, probability, typed claims, evidence references; claim = type, referenced field/entity, operator, value, evidence id; <= 8 claims). The concrete JSON layout, operator vocabulary per type, value shapes and evidence-id pattern are ours, versioned as `rationale_v1`. A JSON Schema file and an independent validator are cross-checked in tests. | `schemas/rationale_v1.json`, `schemas/__init__.py` |
| D-04 | Mixer rule | R | "Isotonic" cannot map three inputs to a scalar by itself. Stratify by verifier state; not-invoked/rejected rows use the triage probability only; accepted rows use `(1-w) p_triage + w p_rationale` with `w` chosen on the SELECTION half by AUPRC; one isotonic fit per stratum (fallback: a global fit on the triage probability). A rejected rationale's probability is never read (tested by perturbation). | `models/mixer.py` |
| D-05 | Verdict consistency | R | A decisive verdict (`fraud`/`legitimate`) needs at least one claim, and the verdict must agree with the rationale probability (fraud: `p >= 0.5`; legitimate: `p < 0.5`). Optional per-field direction hints can add a domain rule. | `verifier/engine.py` |
| D-06 | Cost-sensitive weight form | R | The paper gives the weight (0.50) and the per-class normalisation by `max(c_FN, c_FP)` but not how a weight enters a boosted-tree loss. We use `w = (1 - lambda) + lambda * c_hat` per class. | `models/triage.py::cost_sample_weights` |
| D-07 | Drift-weighted conformal | R | Described only as a variant. Implemented as weighted split conformal (Tibshirani et al.) with exponential recency weights; the half-life is a parameter. Empirical coverage under drift is a measurement, not a guarantee. | `calibration/conformal.py` |
| D-08 | AUPRC convention | R | "Across all unique score thresholds" is read as step-wise average precision over distinct thresholds (tied scores are one threshold). The trapezoid convention is available and the convention is recorded in every manifest. Neither dominates the other. | `evaluation/metrics.py::auprc` |
| D-09 | ECE binning and DI convention | R | S2 reports ECE and a disparate-impact ratio without stating the binning or which rate is in the numerator. ECE: 10 equal-width bins. DI: both the flag-rate ratio and the unflagged-rate ratio are computed and labelled. | `evaluation/metrics.py`, `evaluation/cost.py` |
| D-10 | Whitespace in generated JSON | R | The decoding language is compact JSON (no whitespace) so it stays a small regular language with an exact token mask. Evidence ids are listed in strictly increasing order, which makes them unique without leaving the regular languages. | `models/grammar.py` |
| D-11 | Stage 0 training signal and D2 alignment | R | The paper trains the encoder before the tree model but does not say with what signal (the tree's gradients cannot reach it). A linear head with class-balanced focal loss on the labelled targets is trained and then discarded. For D2 (accounts are nodes, transactions are edges) the 64-dim embedding of a transaction is a function of its endpoint embeddings: `mean` (default), `src`, `dst` or `hadamard`; the policy is written to the manifest. Batches are time-ordered and each uses the snapshot strictly before its earliest sample. | `training/encoder_train.py`, `models/spectral.py::align_edges` |
| D-12 | Scaling for an unseen group | R | Per-currency (D2) and per-timestep (D4) standardisation use only training statistics. A group never seen in training (a later D4 time step) uses POOLED TRAINING statistics; estimating it from the unseen group's own rows would fit on evaluation data. | `data/transforms.py::PerGroupScaler` |
| D-13 | D1 order within a month | R | BAF has no timestamp finer than the month. The "final 10% of the training period, chronologically" validation segment is the last 10% of rows after a stable sort by month, i.e. file order within a month. | `data/splits.py::split_d1` |
| D-14 | Counterfactual stability loss | R | Total loss = CE(target) + 0.25 * CE(counterfactual target | counterfactual evidence). The counterfactual changes one numeric evidence value, removes contradicted claims, keeps verdict and probability, and is re-verified. | `training/objectives.py::make_counterfactual`, `training/rationale_train.py` |
| D-15 | Training rationale targets | R | How the paper's targets were authored is unstated. A deterministic rule builder uses the most atypical numeric fields (training z-scores), a categorical membership, a recent-event window and a visible one-hop path; the verdict follows the TRAINING label. Only verifier-accepted targets are kept. | `training/objectives.py::RuleTargetBuilder` |
| D-16 | Baseline architectures | R | Table 5 names the families only. The settings in `baselines/registry.py` and `baselines/neural.py` are ours and identical across datasets. Isolation Forest is negated into fraud orientation. | `baselines/` |
| D-17 | Robustness applicability and denominator | R | Which dataset/family pairs make sense is not stated (Table 9 names no dataset). `NOT_APPLICABLE` records the reasoning per pair. The evasion denominator is explicit: frauds detected before the edit (default) or all frauds. This repository only SCORES supplied fixed files. | `evaluation/robustness.py` |
| D-18 | Python and library versions | R | The paper reports Python 3.11.7 and Transformers 4.40.1. Tested here: Python 3.10.11 (this machine) with CI on 3.10-3.12, Transformers 4.43.4. Llama 3.1 needs Transformers >= 4.43 (its `rope_scaling` type `llama3`), so the reported 4.40.1 cannot load the specified base model: see `docs/REPRODUCING.md` ("Versions"). | `pyproject.toml` |
| D-19 | LoRA learning rate | P (typo) | Section 3.3.1 prints `2 x 10^4`; Section 3.8.1 prints 0.0002. 2e-4 is used. | `published.py` |
| D-20 | Evidence ego graph | R | Evidence for a graph claim is the directed ego neighbourhood of the entities involved, built only from edges strictly before the prediction time, to a stated hop radius. It is marked `complete` only if the breadth-first expansion finished under the node cap, and absence is provable only up to that radius. | `data/graph.py::ego_edges`, `verifier/evidence.py` |

## Things the repository will not do

* It will not infer a number from the paper and present it as measured. Published values live in `references/reported/`; reproduced values come only from run files.
* It will not generate edited fraud transactions or search for variants that avoid detection. Robustness tables are scored from supplied, frozen files.
* It will not substitute a fixture for a real component on a benchmark run.
